# Office 资源管理测试设计

本测试设计覆盖 `onlyoffice.getpi.work` Release v4 完整 Office Pack 的首次下载、暂停继续、版本升级、完整性检查和自动修复。发布门禁、Cloudflare 本地仿真、单元测试与真实浏览器验收必须同时通过，任一层失败都不得显示“资源已就绪”或继续生产发布。

## 状态契约

| 状态         | 必须满足的条件                                           | 用户操作                       |
| ------------ | -------------------------------------------------------- | ------------------------------ |
| 待安装       | 当前 release 的完整包尚未通过 SHA-256 校验               | 安装完整资源包                 |
| 正在更新     | 唯一的完整包任务正在下载、校验或激活                     | 暂停                           |
| 已暂停       | 当前流保持恢复点，不推进可见进度                         | 继续或取消                     |
| 资源已就绪   | release、包 SHA-256、包字节数和全部 profile 账本完全一致 | 检查并修复                     |
| 资源需要修复 | 包缺失、Range 响应错误、长度不符、哈希失败或存储失败     | 显示结构化原因并重新安装完整包 |

资源版本由 Release Manifest v4 和唯一 Office Pack SHA-256 共同决定。包内包含全部组件和字体；升级不混用两个 release 的字节。

## 自动化矩阵

| 场景            | 断言层级        | 关键断言                                                                |
| --------------- | --------------- | ----------------------------------------------------------------------- |
| 确定性构建      | 单元 + 发布门禁 | 相同输入产生相同包 SHA-256、偏移表、分段哈希和 releaseId                |
| 全新安装        | 单元 + 浏览器   | 一个逻辑包任务按 24 MiB 分段传输、进度单调；完成后六个 profile 同时就绪 |
| 暂停继续        | 单元 + 浏览器   | 暂停后进度稳定；继续后从当前分段恢复，不创建第二个安装任务              |
| 最后 1 MiB 断网 | 浏览器          | 状态转为离线/可重试；恢复后成功收敛，不显示假就绪                       |
| 包长度错误      | 单元            | `Content-Length` 不符时返回 integrity                                   |
| 包哈希错误      | 单元            | 不激活 release、不保留 staging 包、显示完整性错误                       |
| 分段与 Range    | Worker + 浏览器 | 分段完整响应可离线命中；无效范围 416；合法范围准确 206                  |
| 资源 URL 映射   | 浏览器          | JS、CSS、WASM、字典和字体均从同一包分段读取且 MIME 正确                 |
| 兼容回退        | 浏览器          | v3 release 或包临时失败时仍可读取旧内容寻址资源                         |
| 并发标签        | 单元 + 浏览器   | Web Lock 保证一个下载者；广播进度不发生 ping-pong                       |
| PWA 自动更新    | 浏览器          | 脏文档阻止激活；保存后只刷新一次                                        |
| 中英文体验      | 单元 + 浏览器   | “完整 Office 资源包”、阶段、错误和按钮实时切换                          |

## 发布门禁

发布前后必须校验 Release v4：

1. 包对象 SHA-256、字节数、分段哈希和包内资产偏移必须一致。
2. 包的 `bytes=0-7` 必须返回 `206`、8 字节和 `OOBPACK1`。
3. Word/Spreadsheet/Presentation、x2t 和至少一个字体必须通过包内 Range 返回正确 MIME。
4. 先上传 immutable package/release，部署 Worker 并完成 smoke，最后切换 stable pointer。
5. 保留旧 v3 release 和 blobs，不使用破坏性的同步删除。

## Chrome 验收

在全新 Profile 与已有缓存 Profile 各执行一次：

1. 打开资源面板，确认只展示一个完整 Office 资源包、准确大小和一个进度条。
2. 安装期间确认进度单调、暂停后稳定、继续后收敛为就绪。
3. 在最后 1 MiB 断网，确认没有假就绪；恢复网络后重试成功。
4. 断网后读取首个已安装分段，确认仍返回 `OOBPACK1`；随后打开 Word、Spreadsheet、Presentation，确认请求命中同一 `.oobpack` 且编辑、保存、打印正常。
5. 损坏任一分段后执行检查修复，确认重新校验完整包。
6. 切换中英文，确认状态、错误提示和按钮同步切换。
7. 更新 PWA，分别验证无未保存文档自动更新和有未保存文档延迟更新。
