# Office 资源管理测试设计

本测试设计覆盖 `onlyoffice.getpi.work` 的资源版本、首次下载、增量升级、完整性检查、自动修复和字体管理。发布门禁、单元测试与真实浏览器验收必须同时通过，任一层失败都不得显示“资源已就绪”或继续生产发布。

## 状态契约

| 状态         | 必须满足的条件                                                                   | 用户操作                             |
| ------------ | -------------------------------------------------------------------------------- | ------------------------------------ |
| 按需下载     | 当前清单至少一个必需资源尚未完成                                                 | 准备基础资源、安装兼容字体、下载全部 |
| 正在更新     | 有且仅有一个串行资源操作正在执行                                                 | 所有资源操作按钮禁用，进度持续前进   |
| 资源已就绪   | 当前复合资源版本的全部已安装资源均有完成记录；字体文件也存在于专用 Cache Storage | 检查并修复                           |
| 资源需要修复 | 至少一个资源下载、哈希校验或缓存修复失败                                         | 显示具体失败路径和重试提示           |

资源版本由运行时清单与字体清单共同决定。升级时只迁移路径和 revision 都未变化的完成记录；变更或新增资源必须重新下载。

## 自动化矩阵

| 场景             | 断言层级        | 关键断言                                                     |
| ---------------- | --------------- | ------------------------------------------------------------ |
| 全新安装         | 单元 + 浏览器   | 初始为按需下载；完成后文件数、字节数、分类进度一致           |
| 断点续传         | 单元            | 已完成资源不重复下载；失败资源可在下一次操作恢复             |
| HTTP 缓存损坏    | 单元            | 哈希失败后只对损坏资源使用 reload，再次校验通过              |
| HTTP 缓存淘汰    | 单元            | 缓存 miss 后从网络恢复，不丢失其他完成记录                   |
| 字体专用缓存命中 | 单元 + 浏览器   | 检查修复直接校验 Cache Storage，不访问在线字体对象           |
| 在线字体对象 404 | 单元 + 发布门禁 | 操作结束为错误，不停留在下载态；显示准确路径；CI 阻止部署    |
| 对象恢复后重试   | 单元 + 浏览器   | 同一管理器再次修复成功，失败列表清空并恢复就绪               |
| 运行时版本升级   | 单元            | 仅迁移 revision 未变化的资源，清除旧字体缓存分区             |
| 字体清单升级     | 单元 + 发布门禁 | 复合版本变化，新增或变更字体资源重新进入下载队列             |
| 可选字体安装     | 单元            | 共享缩略图、基础字体与目标字体共同完成；其他可选字体不下载   |
| 可选字体移除     | 单元            | 只删除目标字体；共享文件和基础字体保持；字体列表可再次下载   |
| 并发重复操作     | 单元            | 相同操作合并，不同写操作串行，最终快照无过期覆盖             |
| PWA 自动更新     | 浏览器          | 无未保存文档时自动接管；有未保存文档时等待，保存或关闭后更新 |
| 中英文错误体验   | 单元 + 浏览器   | 状态、失败说明、按钮文案随语言即时切换，无硬编码文案         |

## 发布门禁

`scripts/verify-deployed-font-assets.mjs` 必须在 Worker 发布前后分别读取线上字体清单，并对每个带 revision 的 URL 执行 HEAD：

1. 所有对象必须返回成功状态。
2. 返回 `Content-Length` 时必须与清单字节数完全一致。
3. 任何缺失或截断对象都汇总报告并终止发布。
4. 字体资产发布必须先上传对象、最后发布清单；运行时发布不得删除字体对象。

## Chrome 验收

在全新 Profile 与已有缓存 Profile 各执行一次：

1. 打开资源面板，记录 npm 包版本、资源版本与各分类状态。
2. 执行检查并修复，确认操作结束、按钮恢复可用、无 4xx/5xx 请求。
3. 删除一个测试缓存条目后再次修复，确认只重新请求该资源。
4. 离线执行检查，已安装字体必须从 Cache Storage 验证成功。
5. 切换中英文，确认状态、错误提示和按钮同步切换。
6. 更新 PWA，分别验证无未保存文档自动更新和有未保存文档延迟更新。
